02
개념 정의 · WHAT

챗봇이 아니라 내 컴퓨터에서 일하는 동료

Claude Code는 터미널에서 도는 에이전트다. 코드를 복사해 붙여넣는 대신, Claude가 직접 파일을 읽고 고치고 명령을 실행한다.
웹 챗봇으로 코딩할 때
복사 → 붙여넣기
→ 다시 복사
파일 하나 보여주려고 매번 붙여넣고, 받은 코드는 내가 옮겨 심는다. 프로젝트 전체 맥락은 전달할 방법이 없다.
→
Claude Code로 할 때
"로그인 버그 고쳐줘"
→ 알아서 찾고 고친다
저장소를 직접 뒤지고, 테스트를 돌리고, git 작업까지 한다. 다만 모든 변경은 내 승인을 거친다.
붙여넣기를 멈추고 일을 맡기는 것이 핵심이다

터미널

3

07
첫 대화 · FIRST PROMPTS

처음엔 이 세 가지부터 시켜보자

🔍

① 이해시키기

"이 프로젝트 구조를 설명해줘"

가장 안전한 첫 명령. 아무것도 고치지 않고 저장소를 읽기만 한다. Claude가 내 코드를 어떻게 파악하는지 감이 온다.

  • "로그인은 어디서 처리돼?"
  • "이 폴더는 왜 있는 거야?"
🔧

② 작게 고치기

"README 오타를 찾아 고쳐줘"

승인 흐름을 체험한다. 변경 전에 무엇을 바꿀지 보여주고 물어본다. 여기서 diff를 읽는 습관을 들이자.

  • 작은 범위 → 결과 확인 → 다음
  • 한 번에 하나씩 시키는 게 요령
📦

③ 귀찮은 일 맡기기

"변경사항 커밋 메시지 써서 커밋해줘"

바로 체감되는 첫 효용. git 로그 스타일까지 맞춰준다. 테스트 실행이나 로그 분석도 같은 부류다.

  • "테스트 돌리고 실패한 것만 알려줘"
  • "이 에러 로그 원인 찾아줘"
막연하게 "앱 만들어줘"보다 범위가 좁고 결과를 확인할 수 있는 일부터 주는 게 훨씬 잘 된다. 큰 일은 잘게 쪼개서 하나씩.
첫 명령은 읽기만 하는 것으로

08
입력의 기본기 · INPUT

이 네 글자만 알면 절반은 끝

@

파일을 콕 집어 준다

@src/api.ts 리뷰해줘 — 입력하면 경로 자동완성이 뜬다. 찾는 시간을 아껴준다.

/

명령 목록을 연다

맨 앞에 / 를 치면 쓸 수 있는 명령이 전부 뜬다. 외울 필요 없이 여기서 찾으면 된다.

!

셸 명령을 직접 실행

! npm test — Claude를 거치지 않고 바로 실행하고, 그 결과를 보고 Claude가 답해준다.

Ctrl+V

이미지를 붙여넣는다

에러 스크린샷, 디자인 시안을 그대로. macOS iTerm2는 Cmd+V, Windows·WSL은 Alt+V.

\ + Enter

줄바꿈 (전송 안 됨)

어느 터미널에서나 동작한다. Shift+Enter는 터미널에 따라 다르니, 안 되면 /terminal-setup.

?

단축키 도움말

입력창이 비어 있을 때 ? 를 누르면 단축키 패널이 열린다. 까먹었을 때 여기.

외우지 말고 / 와 ? 를 눌러라

가장 중요한 단축키 · PERMISSION MODES

Shift+Tab — 얼마나 맡길지 정하는 다이얼

Claude가 어디까지 물어보고 어디까지 알아서 할지를 정한다. 누를 때마다 순환하고, 현재 모드는 화면 아래에 표시된다.
✋

Manual (기본값)

모든 작업 전에 물어본다

여기서 시작하자. 파일을 고치기 전, 명령을 돌리기 전 매번 승인을 받는다. 느리지만 무슨 일이 일어나는지 다 보인다.

✍️

acceptEdits

파일 편집은 자동 승인

파일 수정은 묻지 않고, 셸 명령은 여전히 물어본다. 방향을 이미 신뢰하는 반복 작업에 쓴다.

📋

plan (플랜 모드)

읽기만 하고 계획을 낸다

초보자에게 제일 유용하다. 소스를 건드리지 않고 탐색해서 계획서를 먼저 준다. 읽어보고 승인하면 그때 실행한다.

큰 작업을 시키기 전엔 플랜 모드로 한 번 돌려보는 습관을 들이자 — /plan 을 앞에 붙이거나 claude --permission-mode plan 으로 시작해도 된다. 계획이 마음에 안 들면 그냥 다시 시키면 되니, 잘못된 수정을 되돌리는 것보다 훨씬 싸다.
처음엔 기본 모드로, 큰 일은 플랜 모드로

안전벨트 · STOP & UNDO

이상하다 싶으면 바로 멈춰라

Esc

하던 일 중단

응답이나 도구 실행을 멈춘다. 지금까지 한 작업은 유지되고 세션도 살아 있다. 방향이 틀렸다 싶으면 끝까지 기다리지 말자.

Esc Esc

되감기 — 최고의 안전장치

입력창이 비어 있을 때 두 번 누르면 되감기 메뉴가 열린다. 코드와 대화를 이전 시점으로 되돌린다.

Ctrl+O

실제로 뭘 했는지 보기

도구 실행 내역이 접혀 있는데, 이걸 누르면 전체 기록이 펼쳐진다. 뭔가 이상할 때 여기서 원인을 찾는다.

Ctrl+C

중단 · 입력 지우기

실행 중이면 중단, 아무것도 안 돌면 입력창을 비운다. 한 번 더 누르면 종료된다.

Ctrl+D

세션 종료

두 번 눌러 나간다. 대화는 저장되니 /resume 으로 언제든 돌아올 수 있다.

기억할 건 두 개뿐이다. 멈추려면 Esc, 되돌리려면 Esc 두 번. 이 둘만 알면 뭘 시켜도 크게 겁낼 일이 없다.

되돌릴 수 있으면 과감하게 시도할 수 있다

첫 주에 쓸 건 여덟 개면 충분하다

명령무엇을 하나언제 쓰나
/init프로젝트용 CLAUDE.md 초안을 만들어준다새 저장소에서 가장 먼저

## 프로젝트 개요
Next.js 기반 사내 대시보드. 인증은 NextAuth 사용.

## 명령어
- 개발 서버: pnpm dev
- 테스트: pnpm test  (커밋 전에 반드시)

## 규칙

시작
/init 한 번이면 초안 완성

Claude가 저장소를 훑어보고 CLAUDE.md 초안을 직접 만들어준다. 거기에 내 규칙 몇 줄만 얹으면 된다.

  • 세션마다 자동으로 읽힌다 — 매번 설명할 필요 없음
  • git에 커밋하면 팀 전체가 같은 규칙을 쓴다
  • 길게 쓰지 말 것 — 짧고 구체적인 규칙이 잘 지켜진다
  • 다듬을 땐 /memory
반복해서 말하고 있다면 파일에 적을 때다

대화 관리 · CONTEXT

대화가 길어지면 정리해야 한다

Claude는 매번 대화 전체를 다시 읽는다. 그래서 세션이 길어질수록 느려지고 흐려진다. 초보자가 가장 많이 놓치는 부분이다.
📊

/context

무엇이 자리를 차지했나

파일·대화·시스템 프롬프트가 각각 얼마나 쓰는지 보여준다. 정리할 때가 됐는지 판단하는 기준.

🗜️

/compact

요약해서 공간 확보

지금까지의 대화를 압축한다. 같은 작업을 계속 이어갈 때. 뒤에 지시를 붙이면 그걸 남긴다.

🧹

/clear

깨끗하게 새로 시작

다른 작업으로 넘어갈 때는 이쪽. 이전 대화는 저장돼 있으니 /resume 으로 돌아갈 수 있다.

간단한 기준 — 같은 일을 계속하면 /compact, 다른 일로 넘어가면 /clear. 새 작업을 이전 대화 위에 얹는 것이 답을 흐리게 만드는 가장 흔한 원인이다.
작업이 바뀌면 대화도 바꿔라

터미널 밖에서도 · BEYOND THE CLI

터미널이 유일한 입구는 아니다

🖥️

데스크톱 앱

macOS · Windows · Linux

터미널 없이 Claude Code를 쓴다. 명령줄이 부담스러운 분에게 가장 편한 출발점.

  • 같은 기능, 그래픽 인터페이스
  • 설정과 CLAUDE.md는 그대로 공유
🧩

에디터 안에서

VS Code 확장 · JetBrains 플러그인

쓰던 에디터에서 그대로 부른다. 변경 내용을 에디터의 diff 화면으로 확인할 수 있다.

  • 파일을 오가며 작업할 때 편하다
  • 터미널 세션과 함께 써도 된다
⚡

한 줄로 물어보기

claude -p "질문"

16
함정 · COMMON MISTAKES

처음에 다들 겪는 여섯 가지

📂

엉뚱한 폴더에서 시작

홈 디렉터리에서 켜면 프로젝트를 못 본다. 반드시 프로젝트 폴더로 cd 한 뒤 실행하자.

⏎

확인 없이 승인 연타

diff를 안 읽고 넘기면 나중에 원인을 못 찾는다. 처음 며칠은 기본 모드에서 하나씩 읽자.

🗑️

git 없이 큰 작업

커밋해 두지 않으면 되돌릴 기준점이 없다. 작업 전에 커밋해 두는 것이 최고의 안전장치다.

🧵

한 대화로 종일 작업

작업이 바뀌면 /clear. 이전 맥락이 남아 답이 흐려지는 게 가장 흔한 원인이다.

🏔️

너무 큰 일을 한 번에

"앱 만들어줘"는 어긋나기 쉽다. 확인 가능한 단위로 쪼개서 시키자.

📰

오래된 글 따라하기

변화가 빠른 도구다. 명령이 안 먹으면 공식 문서를 보거나 / 로 확인하자.

작업 전 커밋, 작업 후 확인 — 이 둘이면 안전하다
