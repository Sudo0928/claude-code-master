02
문제 인식 · WHY

CLAUDE.md에 적어놨는데 왜 안 지키지?

"커밋 전에 테스트 돌려", ".env는 절대 건드리지 마" — 분명히 적어뒀는데 열 번 중 아홉 번만 지킨다. 프롬프트는 지시가 아니라 부탁이기 때문이다. 지켜야만 하는 규칙이라면, 모델의 판단에서 꺼내 코드로 내려야 한다.
지금까지 · 프롬프트로 부탁
"이렇게 해줘"라고
매번 적어둔다
대화가 길어지면 잊고, 컨텍스트가 밀리면 사라진다. 지켰는지 확인하는 것도 결국 사람 몫. 확률적이다.
→
이제부터 · 훅으로 강제
특정 시점에

03
개념 정의 · WHAT

훅(Hook)은 라이프사이클 이벤트 핸들러다

Claude Code가 일하는 도중 정해진 시점마다 자동으로 실행되는 내가 정의한 명령. 도구를 쓸지 말지 모델이 고르는 게 아니라, 내가 건 조건에 맞으면 무조건 뛴다.
1

실행 시점이 정해져 있다

세션 시작, 프롬프트 제출, 도구 실행 전후, 응답 종료… 30가지가 넘는 이벤트 중에서 고른다. 이벤트가 뜨고 매처가 맞으면 그때 실행된다.

2

결정론적이다 — LLM의 판단이 아니다

규칙을 프롬프트가 아니라 앱 레벨 코드로 바꾸는 일. 그래서 "기대할 때마다 매번" 실행된다.

3

JSON으로 듣고, 종료 코드로 답한다

이벤트 정보가 stdin에 JSON으로 들어오고, 스크립트는 종료 코드나 stdout JSON으로 "통과·차단·이 말 전해줘"를 돌려준다.

4

설정 파일 한 줄이면 끝난다

settings.json에 선언하는 게 전부. 프로젝트에 커밋하면 팀 전체가 같은 규칙 아래서 일한다.

훅은 '제안'을 실행되는 코드로 바꾼다

04
역할 분담 · WHERE IT FITS

CLAUDE.md · 권한 · 훅, 뭘 어디에 쓰나

셋 다 Claude의 행동을 다루지만 성격이 완전히 다르다. 정적인 규칙은 위로, 강제해야 할 건 아래로 내려보내는 게 원칙이다.
📝

CLAUDE.md

성격 · 설득 (soft)

변하지 않는 프로젝트 관례. 스크립트를 돌리지 않고 그냥 읽힌다. 강제력은 없지만 비용도 없다.

  • 코딩 컨벤션, 디렉터리 구조 설명
  • "이 저장소는 bun을 쓴다"
  • 항상 참인 정적 정보의 표준 위치
🚧

권한 규칙

성격 · 필터 (hard)

정적인 allow / ask / deny. 하드 차단이 필요하면 훅이 아니라 여기다. deny 규칙은 훅의 allow보다 세다.

  • 도구 이름·인자 패턴으로 허용/거부
  • 조직 관리 설정으로 배포 가능
  • 판단이 필요 없는 정책은 전부 여기
⚡

Hooks

성격 · 강제 + 반응 (dynamic)

동적 검사와 사후 반응. 규칙으로 표현 못 하는 것, 그리고 "끝난 뒤에 해야 하는 일"이 훅의 영역이다.

  • 편집 직후 포맷·린트·테스트
  • 명령 내용을 읽고 조건부 차단
  • 로깅·감사·알림·컨텍스트 주입
확장 수단은 더 있다 — 절차 지식은 Skills, 무거운 작업 격리는 서브에이전트, 이 셋을 묶어 배포하려면 플러그인. 훅은 그중 "반드시 실행되어야 하는 것"을 담당한다.
막아야 하면 권한, 반응해야 하면 훅

07
설정 구조 · ANATOMY

훅 설정은 딱 3층이다

.claude/settings.json
{
  "hooks": {
    "PreToolUse": [                ← ① 이벤트
      {
        "matcher": "Bash",          ← ② 매처 그룹
        "hooks": [
          {                          ← ③ 핸들러
            "type": "command",
            "if": "Bash(rm *)",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh",
            "args": []
          }
        ]
      }
    ]
  }
}
1

이벤트

언제 끼어들지 고른다. 라이프사이클 이름이 그대로 키가 된다.

2

매처 그룹

그 이벤트 중 어떤 경우에만 뛸지 좁힌다. 생략하면 매번 실행.

3

핸들러

실제로 실행되는 것. 여러 개를 나열하면 전부 병렬로 돈다.

${CLAUDE_PROJECT_DIR}는 프로젝트 루트. 스크립트 경로를 쓸 땐 args를 붙여 셸을 거치지 않는 게 안전하다(공백·따옴표 문제 없음).
이벤트 → 매처 → 핸들러, 이 3층이 전부다

09
범위 좁히기 · MATCHER

매처는 쓴 대로 해석된다

매처에 들어간 문자의 종류에 따라 정확 일치인지 정규식인지가 갈린다.
매처 값해석예시
"*" · "" · 생략전부 일치이벤트가 뜰 때마다 항상
문자·숫자·_ - , |·공백만정확 일치 (목록 가능)Bash / Edit|Write / Edit, Write
그 외 문자가 하나라도 포함정규식 (앵커 없음)mcp__memory__.* / ^Notebook
⚠️

자주 틀리는 지점

  • Edit.*는 NotebookEdit까지 잡는다 → ^Edit$로 앵커를 걸어라
  • 매처는 대소문자를 구분한다
  • 이벤트마다 보는 값이 다르다 — 도구 이름 · startup·resume·clear · 알림 종류 · 에이전트 이름
🎯

if — 인자까지 좁히기

매처가 도구 이름까지라면, if는 인자까지 본다. 조건이 맞을 때만 프로세스가 뜬다.

  • "Bash(git *)" — git 명령일 때만
  • "Edit(*.ts)" — 타입스크립트 편집에만
  • 규칙은 하나만 (&& · || 없음) → 조건마다 핸들러를 따로
  • 도구 이벤트에서만 동작 · 파싱 실패 시 그냥 실행(fail open)
그룹은 matcher로, 인자는 if로 — 하드 차단은 권한 규칙으로

10
입력과 출력 · I/O

JSON으로 듣고, 종료 코드로 답한다

stdin — 훅이 받는 JSON
{
  "session_id": "abc123",
  "cwd": "/Users/gym/my-project",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "rm -rf /tmp/build"
  }
}
공통 필드(session_id cwd hook_event_name)에 이벤트별 필드가 얹힌다. UserPromptSubmit은 prompt, SessionStart는 source를 받는다.
exit 0

이의 없음 · 그대로 진행

PreToolUse에서 0은 승인이 아니다 — 평소 권한 흐름이 그대로 이어진다. 단 UserPromptSubmit · SessionStart는 stdout이 컨텍스트로 주입된다.

exit 2

차단 · stderr가 Claude에게 간다

도구 호출이 취소되고, stderr에 쓴 이유가 피드백으로 전달돼 Claude가 방법을 바꾼다. 이벤트마다 효과는 다르다(프롬프트 취소, 못 멈추게 하기 등).

그 외

비차단 에러 · 작업은 진행된다

트랜스크립트에 hook error와 stderr 첫 줄만 뜨고 아무것도 막지 못한다.

⚠️ exit 1은 차단이 아니다. 유닉스 관례와 달리 1은 "에러지만 계속"이다. 정책을 강제할 생각이면 반드시 exit 2.
막고 싶으면 2로 나가라

11
정밀 제어 · JSON OUTPUT

종료 코드로 부족하면 JSON으로

종료 코드는 막거나 가만히 있거나 둘뿐 — exit 0 + stdout JSON이면 훨씬 정밀해진다.
🚦

PreToolUse · 허가 결정

permissionDecision = allow | deny | ask

deny면 호출이 취소되고 이유가 Claude에게 간다. ask는 사용자에게 묻는다. updatedInput으로 인자를 바꿔치기할 수도 있다.

🛑

상위 decision · 차단

{ "decision": "block", "reason": "…" }

UserPromptSubmit · PostToolUse · Stop 등이 쓰는 방식. Stop에서 쓰면 대화가 계속되며 reason이 다음 지시가 된다.

🧠

컨텍스트 주입

hookSpecificOutput.additionalContext

현재 브랜치, 배포 대상 같은 상태 정보를 밀어 넣는다. 명령문이 아니라 사실 문장으로 — 지시문처럼 쓰면 프롬프트 인젝션 방어에 걸린다.

⏹️

전체 중단 · 사용자 알림

{ "continue": false, "stopReason": "…" }

continue:false는 이벤트와 무관하게 Claude를 완전히 멈춘다. systemMessage는 사용자에게 보이는 경고.

exit 2와 JSON을 섞지 마라 — JSON은 exit 0일 때만 처리된다. 그리고 allow는 deny 규칙을 뚫지 못한다.
훅은 조일 수는 있어도 풀 수는 없다

12
핸들러 종류 · 5 TYPES

훅이 셸 명령만 있는 건 아니다

⌨️

command

기본값 · 타임아웃 600초

셸 명령이나 스크립트. stdin으로 JSON을 받고 종료 코드·stdout으로 답한다.

  • args를 주면 셸 없이 바로 실행 — 경로에 공백이 있어도 안전
🌐

http

url · headers · allowedEnvVars

이벤트 JSON을 그대로 POST. 응답 바디가 stdout 역할을 한다. 팀 공용 감사·검증 서버에 어울린다.

  • 상태 코드만으론 차단 불가 — 막으려면 2xx + 결정 JSON
🔌

mcp_tool

server · tool · input

이미 연결된 MCP 서버의 툴을 호출한다. 툴의 텍스트 출력이 stdout처럼 처리된다.

  • 입력값 꽂기 ${tool_input.file_path} · 연결 전이면 비차단 에러
💭

prompt — 판단이 필요할 때

기본 Haiku · 30초 · { "ok": false, "reason": "…" }

규칙으로 표현할 수 없는 판단을 모델에게 맡긴다. 예: Stop 훅에서 "작업이 다 끝났나?"를 묻는다.

🕵️

agent — 실제로 확인할 때

실험적 · 60초 · 최대 50턴 · 도구 사용 가능

서브에이전트가 파일을 읽고 명령을 돌려 실제 상태를 확인한 뒤 판단한다.

타임아웃 기본값 — command 600초, prompt 30초, agent 60초.
결정론이면 command, 판단이면 prompt, 검증이면 agent

오늘 바로 거는 훅 3종

🎨

편집하면 자동 포맷

"PostToolUse"
matcher: "Edit|Write"
jq -r '.tool_input.file_path'
  | xargs npx prettier --write

포맷 얘기를 다시 안 해도 된다. 파일을 고칠 때마다 Prettier가 뒤따라 돈다.

  • 편집 도구에만 걸리게 매처로 좁힘
  • jq로 파일 경로만 뽑아 전달
  • eslint --fix를 나란히 하나 더
🛡️

보호 파일 차단

"PreToolUse"
matcher: "Edit|Write"
.claude/hooks/protect-files.sh

.env · package-lock.json · .git/ 를 건드리면 exit 2로 막고 이유를 돌려준다.

  • 차단 이유를 읽고 Claude가 방향을 바꾼다
  • 스크립트는 chmod +x 필수
  • 경로는 ${CLAUDE_PROJECT_DIR} 기준으로
🧠

matcher: "compact"

컴팩션에 날아간 규칙을 되살린다. 이 이벤트에선 stdout이 그대로 컨텍스트가 된다.

  • git log --oneline -5처럼 동적 출력도 가능
  • 매 세션 고정 규칙이면 CLAUDE.md가 낫다
알림도 한 줄이다 — Notification 이벤트에 macOS는 osascript, 리눅스는 notify-send. 자리를 비워도 Claude가 나를 기다리는 순간을 놓치지 않는다.
포맷 · 차단 · 주입 — 이 셋만 걸어도 체감이 다르다

심화 · WALKTHROUGH

rm -rf를 막는 훅, 한 줄씩

.claude/hooks/block-rm.sh
#!/bin/bash
COMMAND=$(jq -r '.tool_input.command')

if echo "$COMMAND" | grep -q 'rm -rf'; then
  jq -n '{
    hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: "위험한 명령이라 훅이 막았습니다"
    }
  }'
else
  exit 0   # 결정 없음 → 평소 권한 흐름
fi
1

이벤트가 뜬다

Claude가 rm -rf /tmp/build를 실행하려 한다. tool_input이 JSON으로 stdin에 꽂힌다.

2

두 겹으로 걸러진다

matcher가 Bash를, if가 rm *를 맞춰야 스크립트가 뜬다. npm test면 프로세스조차 안 뜬다.

3

결정이 돌아간다

deny + 이유. 호출은 취소되고, Claude는 이유를 읽고 다른 방법을 찾는다.

같은 이벤트에 훅이 여러 개면 전부 병렬로 돌고, 결과는 가장 제한적인 것이 이긴다(deny → defer → ask → allow). 한 훅이 deny해도 다른 훅의 부수효과는 취소되지 않는다.
차단의 정석 — PreToolUse + deny + 이유

15
함정과 보안 · PITFALLS

여기서 다들 한 번씩 넘어진다

🔐

훅에는 샌드박스가 없다

내 자격증명과 권한 그대로, 에이전트 루프 도중 자동으로 실행된다. 남의 설정을 그대로 붙여넣지 말고, 등록 전에 반드시 코드를 읽어라. 조직이라면 관리 설정으로 승인된 훅만 허용할 수 있다.

⚠️

exit 1은 막지 못한다

유닉스 관례와 달리 1은 "에러지만 계속 진행"이다. 정책 강제는 반드시 exit 2. 스크립트가 실패했을 때 조용히 통과하고 있진 않은지 확인하자.

⏪

PostToolUse는 되돌릴 수 없다

이미 실행된 뒤에 뛴다. 진짜로 막아야 하는 건 PreToolUse. Post는 검사·포맷·피드백 용도로만 생각하는 게 맞다.

🔁

Stop 훅 무한 루프

연속 8회 차단하면 강제로 풀린다. 입력의 stop_hook_active가 true면 조기 종료하도록 짜야 한다.

🕳️

Bash로도 파일은 바뀐다

Edit|Write만 걸면 sed -i나 리다이렉션은 못 잡는다. 감사·컴플라이언스 목적이면 Stop 훅에서 워킹트리를 한 번 훑어라.

🔧

안 될 때 · 끄고 싶을 때

claude --debug-file /tmp/claude.log로 전 과정을 남기고, Ctrl+O로 트랜스크립트를 본다. 전부 끄려면 "disableAllHooks": true(개별 비활성화는 없다).

JSON 파싱 에러가 뜬다면 셸 프로필의 echo가 stdout을 오염시킨 경우가 많다 — 인터랙티브일 때만 출력하도록 감싸자. -p 모드에선 PermissionRequest가 뜨지 않으니 PreToolUse를 쓴다.
훅은 내 권한으로 실행된다 — 붙이기 전에 읽어라
