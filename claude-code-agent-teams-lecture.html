02
문제 인식 · WHY

혼자서는 스스로를 반박하지 못한다

단일 세션은 그럴듯한 가설 하나를 찾으면 거기서 탐색을 멈춘다. 앵커링 때문이다. 서브에이전트를 써도 서로 대화를 못 하니 반박이 일어나지 않는다. Agent Teams는 이 구조적 한계를 겨냥한다.
한 명이 순차적으로
가설 하나를 찾고
거기에 갇힌다
먼저 떠오른 설명 쪽으로 이후 조사가 전부 기울어진다. 코드 리뷰도 마찬가지 — 한 번에 한 종류의 문제만 눈에 들어온다.
→
여러 명이 서로 논쟁하며
가설을 서로
깨뜨리려 든다
각자 독립적으로 조사하고 상대의 이론을 반증하려 시도한다. 살아남은 가설이 진짜 원인일 확률이 훨씬 높다.
공식 문서가 꼽는 강점 영역은 넷이다 — 리서치·리뷰, 새 모듈·기능 개발, 경쟁 가설 디버깅, 프런트·백·테스트를 넘나드는 작업. 공통점은 쪼갰을 때 서로 기다릴 필요가 없다는 것이다.
문제는 프롬프트가 아니라 조직 구조였다

이 변수가 없으면 세션 시작 시 팀이 구성되지 않고, 팀 디렉터리도 안 생기고, Claude가 팀메이트를 제안하지도 스폰하지도 않는다.

실험 단계라는 뜻

세션 재개·태스크 조율·종료 동작에 알려진 제약이 있다. 팀 생성/삭제를 하던 TeamCreate·TeamDelete 도구는 v2.1.178에서 사라졌다 — 이제 스폰하면 팀이 생기고, 세션이 끝나면 자동 정리된다.

셸 환경변수로 켜도 된다. 오래된 블로그에 나오는 "먼저 팀을 만들고 이름을 정하라"는 단계는 더 이상 필요 없다.

06
구성 요소 · ARCHITECTURE

팀은 네 조각으로 되어 있다

1

팀 리드 — 내 메인 세션

팀메이트를 스폰하고 일을 나누고 결과를 종합한다. 리드는 세션이 끝날 때까지 고정이다 — 팀메이트를 리드로 승격시킬 수 없다.

2

팀메이트 — 별개의 Claude Code 인스턴스

서브에이전트가 아니라 온전한 세션이다. 각자 컨텍스트 창을 갖고, 스폰될 때 CLAUDE.md·MCP·스킬을 자기 몫으로 로딩한다.

3

공유 태스크 리스트 — 파일 기반 작업 보드

대기 · 진행 중 · 완료 세 상태에 의존 관계까지 걸린다. 동시에 같은 태스크를 집으려 할 때는 파일 잠금으로 충돌을 막는다.

4

메일박스 — 에이전트 간 메시지

각 에이전트마다 JSON 파일 한 개. 리드가 폴링할 필요 없이 메시지가 자동 배달된다.

저장 위치는 세션 ID 앞 8자로 만든 이름 아래다 — 팀 설정은 ~/.claude/teams/{팀이름}/, 태스크는 ~/.claude/tasks/{팀이름}/. 팀 설정은 손으로 고치지 말 것(다음 상태 갱신 때 덮어쓰인다). 태스크 디렉터리는 남아서 재개된 세션이 이어받는다.

첫인상 ③ · 화면 읽기

에이전트 패널 다루는 법

↑ ↓

팀메이트 선택

프롬프트 입력창 아래 패널에서 위아래로 고른다.

Enter

대화 열고 직접 메시지

선택한 팀메이트의 트랜스크립트를 열고 바로 지시를 보낼 수 있다.

Esc

그 팀메이트의 턴 중단

방향이 틀렸다 싶으면 끝까지 기다리지 말자.

x / Ctrl+T

정지 · 태스크 목록 토글

x는 선택한 팀메이트를 멈추고, Ctrl+T는 태스크 보드를 켜고 끈다.

👻

사라진 줄은 죽은 게 아니다

패널의 모든 에이전트가 유휴가 되면 30초 뒤 줄이 숨겨진다. 팀메이트는 계속 살아 있고, 다음 턴에 다시 나타난다. 이름을 불러 메시지를 보내면 즉시 돌아온다.

📚

넷 이상 놀고 있으면 접힌다

유휴 팀메이트가 셋을 넘으면 나머지는 2 idle agents 같은 한 줄로 합쳐진다. Enter로 펼치고 Esc로 다시 접는다. 작업 중이거나 실패한 팀메이트는 항상 자기 줄을 지킨다.

팀메이트는 보고 대상이 아니라 대화 상대다

설정 · DISPLAY & MODEL

어떻게 보여줄지와 무엇으로 돌릴지

🖥️

표시 모드

기본값 in-process · teammateMode 설정

in-process는 전부 한 터미널 안에서 돈다. 추가 설치가 필요 없고 어느 터미널에서나 된다.

  • split panes는 팀메이트마다 창을 준다 — tmux 또는 iTerm2 필요
  • VS Code 내장 터미널·Windows Terminal·Ghostty는 분할 미지원
  • 한 세션만 바꾸려면 claude --teammate-mode auto
🧠

모델 지정

/config → Default teammate model

팀메이트는 리드의 /model 선택을 자동으로 물려받지 않는다. 프롬프트에서 직접 지정하는 게 가장 확실하다.

  • "팀메이트 4명, 각자 Sonnet으로"처럼 명시
  • 리드를 따르게 하려면 Default (leader's model) 선택
  • 추론 강도(effort)는 리드 것을 물려받는다
스폰된 뒤에는 팀메이트의 모델과 fast 모드가 고정된다 — 팀메이트를 보고 있을 때 /model·/fast를 쳐도 리드에만 적용된다. 조직이 모델 허용 목록을 걸어둔 경우, 막힌 값은 허용된 다른 모델로 자동 대체된다.
모델은 스폰할 때 정해진다

운영 ① · 태스크

일을 나누는 두 가지 방식

📌

리드가 배정한다

"이 태스크는 리뷰어에게 줘"

어떤 일을 누구에게 줄지 내가 리드에게 지시한다. 역할이 뚜렷하게 갈릴 때 예측 가능해서 좋다.

🙋

팀메이트가 스스로 집는다

자가 클레임 (self-claim)

하나를 끝내면 배정되지 않고 막히지 않은 다음 태스크를 알아서 집는다. 놀지 않게 만드는 기본 동작.

🚦

세 가지 상태

대기 · 진행 중 · 완료. 상태 관리만으로 팀 전체의 진행이 보인다.

⛓️

의존 관계

의존이 안 풀린 태스크는 집을 수 없다. 선행이 완료되면 자동으로 풀린다.

🔒

파일 잠금

여럿이 동시에 같은 태스크를 집으려 해도 경쟁 상태가 나지 않는다.

태스크 보드가 곧 팀의 상태다

🔑

권한은 리드에서 물려받는다

스폰 시점에 전원이 리드와 같은 권한 모드로 출발한다. 리드가 --dangerously-skip-permissions면 팀메이트도 전부 그렇다.

승인 요청은 리드로 모인다

팀메이트의 권한 프롬프트가 전부 리드 세션에 뜬다. 여기서 내가 직접 승인한다.

🛡️

메시지는 사용자 승인이 아니다

Claude Code는 수신자에게 "이건 다른 Claude 세션에서 온 것"이라고 알린다. 거부당한 팀메이트가 다른 팀메이트를 시켜 우회할 수 없다.

자동 모드에서는 분류기가 에이전트가 보내는 모든 메시지를 배달 전에 검사한다 — 평문이든 종료 요청·플랜 승인 응답 같은 구조화된 메시지든 마찬가지다. 차단된 메시지는 수신자에게 아예 도달하지 않는다. 팀메이트가 전해온 "승인됐다"는 주장도 신뢰할 수 없는 입력으로 취급된다.

베스트 프랙티스 · BEST PRACTICES

잘 굴리는 사람들의 여섯 습관

📝

스폰 프롬프트에 맥락을 담아라

팀메이트는 리드의 대화 이력을 물려받지 않는다. 무엇을 어디서 왜 보는지, 작업별 세부를 스폰 문장에 직접 넣어야 한다.

🎓

리서치·리뷰부터 시작하라

PR 리뷰, 라이브러리 조사, 버그 추적처럼 코드를 쓰지 않는 일이 첫 연습으로 가장 좋다.

🗂️

파일 소유권을 나눠라

둘이 같은 파일을 고치면 덮어쓰기가 난다. 팀메이트마다 다른 파일 집합을 갖게 쪼갠다.

🏷️

이름을 미리 정해줘라

나중 프롬프트에서 부르려면 이름이 필요하다. 스폰할 때 뭐라고 부를지 지정하자.

✋

리드가 직접 일하면 말려라

리드가 팀메이트를 안 기다리고 스스로 구현할 때가 있다. "팀메이트가 끝날 때까지 기다려"라고 하면 된다.

👀

지켜보고 방향을 틀어라

무인 방치가 길수록 헛수고 위험이 커진다. 중간중간 들여다보고 결과가 오는 대로 종합하자.

권한 프롬프트가 너무 자주 뜬다면 팀을 띄우기 전에 자주 쓰는 작업을 권한 설정에서 미리 허용해 두자 — 팀메이트 수만큼 프롬프트가 늘어나기 때문이다.
팀메이트는 내 대화를 모른다 — 다 적어줘라

애초에 중첩 팀이 불가능하다 — 팀메이트는 자기 팀메이트를 못 만든다. 나머지 셋에 스폰 프롬프트 좁히기를 더한 넷이 공식 권고다.
A5② 신뢰할 수 없는 입력으로 처리
에이전트 간 메시지는 사용자 승인이 아니다. 거부당한 팀메이트가 남을 시켜 우회하는 경로가 막혀 있다.
