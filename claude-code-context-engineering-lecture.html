문제 인식 · WHY

루트 파일 하나는 반드시 둘 중 하나로 망가진다

공식 문서의 표현 그대로다 — 저장소가 커지면 루트 CLAUDE.md 하나는 "모든 서브시스템의 규약을 담느라 비대해지거나, 쓸모없을 만큼 일반적인 내용에 머문다". 중간은 없다.
비대해지는 경우
API 작업 중에
모바일 규약을 읽는다
지금 하는 일과 무관한 지시가 컨텍스트를 차지한다. 토큰만 쓰는 게 아니라 — 파일이 길수록 지시 준수율 자체가 떨어진다.
→
일반론에 머무는 경우
"코드를 깔끔하게
작성하세요"
모든 팀에 맞추려다 검증 불가능한 문장만 남는다. 이런 지시는 있으나 마나이며, 정작 필요한 구체적 규약은 아무 데도 없다.
해결의 방향은 하나다 — 지시를 없애는 게 아니라, 읽히는 시점을 옮기는 것. 이 강의는 그 시점을 제어하는 세 가지 장치를 다룬다.
문제는 양이 아니라 타이밍이다

03
전제 · BUDGET

길어질수록 덜 지킨다

📏

200줄이 기준선

공식 권고는 파일당 200줄 미만. 넘으면 컨텍스트를 더 쓰고 준수율이 떨어진다고 명시돼 있다.

📥

길이와 무관하게 전부 로드

CLAUDE.md에는 잘라 읽는 상한이 없다. 1000줄이면 1000줄이 다 들어간다 — 알아서 요약해 주지 않는다.

💬

시스템 프롬프트가 아니다

CLAUDE.md는 시스템 프롬프트 뒤에 붙는 사용자 메시지로 전달된다. 강제 설정이 아니라 맥락이라서 준수가 보장되지 않는다.

🔒

반드시 막아야 한다면 훅으로

"커밋 전에 무조건 린트", "이 경로는 절대 수정 금지"처럼 판단에 맡기면 안 되는 것은 CLAUDE.md가 아니라 PreToolUse 훅이나 permissions.deny로 건다. 훅은 Claude의 결정과 무관하게 실행된다.

✍️

검증 가능한 문장으로 쓴다

"들여쓰기는 2칸" > "포맷을 잘 맞춰라"
"커밋 전 npm test 실행" > "변경을 테스트해라"
"API 핸들러는 src/api/handlers/" > "파일을 정리해라"

블록 단위 HTML 주석 <!-- 유지보수 메모 -->은 컨텍스트에 주입되기 전에 제거된다. 사람용 메모는 여기에 적으면 토큰을 한 톨도 쓰지 않는다(코드 블록 안의 주석은 그대로 유지된다).
읽히는 모든 줄은 비용이자 잡음이다

05
전체 지도 · THREE GRADES

모든 지시는 세 등급 중 하나에 속한다

GRADE 1 · ALWAYS

항상 로드

CLAUDE.md · paths 없는 rules

세션 시작 시 무조건 컨텍스트에 들어간다. 어느 파일을 만지든 필요한 것만 여기 둔다 — 빌드 명령, 저장소 지도, 공통 규약.

GRADE 2 · ON MATCH

매칭될 때 로드

paths 규칙 · 폴더별 CLAUDE.md

Claude가 해당 파일을 실제로 읽을 때 들어온다. 코드베이스의 특정 부분에만 해당하는 규약이 여기 속한다. 이 강의의 본체다.

GRADE 3 · ON DEMAND

필요할 때 로드

스킬 · 플러그인

Claude가 관련 있다고 판단하거나 사용자가 부를 때만 본문이 들어온다. 여러 단계짜리 절차와 참조 자료가 여기 속한다.

RULE
배치 기준
공식 문서의 한 문장이 기준을 다 담는다 — "여러 단계짜리 절차이거나 코드베이스의 한 부분에만 해당한다면, 스킬이나 path 스코프 규칙으로 옮겨라"
이 강의는 1부 무엇이 언제 로드되는가 → 2부 .claude/rules/ 조건부 규칙 → 3부 폴더별 CLAUDE.md 분산 → 4부 통합 설계 순으로 간다.
등급을 정하는 것이 설계의 첫 단계다

1부 ④ · 시작 위치

어디서 claude를 치느냐가 판을 정한다

시작 위치파일 접근 범위시작 시 로드되는 CLAUDE.md어울리는 작업
저장소 루트 모든 파일 루트만. 하위는 읽을 때 온디맨드로 합류 여러 패키지·서브시스템에 걸친 작업

⚠️

settings.json은 상속되지 않는다

CLAUDE.md는 상위 디렉터리까지 훑어 올라가지만, .claude/settings.json은 시작한 디렉터리에서만 읽힌다. 루트의 settings.json은 루트에서 시작했을 때만 적용된다.

→ 하위 디렉터리에서 세션을 여는 팀이라면 각 패키지의 .claude/settings.json이 자기 완결적이어야 한다.

// `@README` 는 그냥 텍스트로 남는다
최대 4홉

재귀 import의 깊이 한계

import된 파일이 또 import할 수 있지만 네 단계까지다.

상대 경로

작업 디렉터리 기준이 아니다

import 문을 담고 있는 파일을 기준으로 풀린다. 여기서 실수가 잦다.

외부 경로

승인 대화상자가 한 번 뜬다

프로젝트 메모리의 import가 작업 디렉터리 밖을 가리키면 최초에 확인을 받는다. 거절하면 그대로 비활성 상태로 남는다. 사용자 스코프 파일은 내가 쓴 것이라 묻지 않는다.

🧨

가장 흔한 착각 — "쪼갰으니 가벼워졌겠지"

import된 파일은 시작 시점에 전부 펼쳐져 컨텍스트에 들어간다. 파일을 열 개로 나눠 import해도 토큰은 1바이트도 줄지 않는다. import는 사람이 관리하기 좋으라고 있는 기능이지 컨텍스트 절약 장치가 아니다. 실제로 줄이려면 다음 파트의 paths: 규칙이나 폴더별 배치를 써야 한다.

쪼개는 것과 미루는 것은 다르다

🔎

/context — 지금 무엇이 들어와 있나

Memory files 항목에 실제로 로드된 파일이 나열된다. 여기 없으면 Claude는 그 파일을 못 보고 있는 것이다. "왜 안 지키지?" 싶을 때 제일 먼저 볼 화면이다.

📝

/memory — 목록과 편집

사용자·프로젝트 스코프의 메모리 파일 위치를 아직 없는 것까지 보여 주고, 고르면 에디터로 열어 준다. 없는 파일을 고르면 만들어 준다. 자동 메모리 토글도 여기에 있다.

🪝

InstructionsLoaded 훅 — 언제 왜 로드됐나

어떤 지시 파일이 언제, 어떤 이유로 로드되는지 기록한다. path 스코프 규칙과 하위 폴더 지연 로딩을 디버깅할 때 결정적이다 — 규칙이 안 걸리는 이유를 눈으로 볼 수 있는 유일한 방법이다.

🩺

/doctor — 비대해진 CLAUDE.md 다듬기

커밋된 CLAUDE.md에 대해 줄일 곳을 제안한다. 디렉터리 구조·의존성 목록·아키텍처 개요처럼 코드베이스에서 유추 가능한 내용은 덜어내고, 함정·판단 근거·기본값과 다른 규약은 남긴다.

보이지 않는 컨텍스트는 고칠 수 없다

2부 ① · RULES 구조

규칙 폴더는 한 파일 한 주제다

your-project/ ├── .claude/ │ ├── CLAUDE.md # 프로젝트 메인 지시 │ └── rules/ │ ├── code-style.md # 코드 스타일 │ ├── testing.md # 테스트 규약 │ ├── security.md # 보안 요구사항 │ └── frontend/ │ └── components.md # 하위 폴더도 OK └── src/
모든 .md가 재귀적으로 발견된다. 규모가 커지면 frontend/·backend/처럼 폴더로 묶어도 된다.
🏷️

파일명이 곧 목차다

testing.md·api-design.md처럼 내용이 드러나는 이름을 쓴다. 팀이 유지보수할 때 어디를 고쳐야 할지가 파일명에서 보여야 한다.

⚖️

우선순위는 .claude/CLAUDE.md와 동급

paths가 없는 규칙은 프로젝트 CLAUDE.md와 같은 우선순위로 시작 시 로드된다. 별도 계층이 아니라 같은 층에 놓인다.

🎚️

--setting-sources와의 관계

project를 빼면 프로젝트 규칙은 건너뛴다. v2.1.211 이전에는 온디맨드로 로드되는 규칙(path 스코프·중첩 rules)이 제외했는데도 로드됐다.

주제별로 쪼개면 팀이 고칠 수 있다

중괄호는 더하기가 아니라 곱하기다

중괄호 그룹은 패턴 수를 곱한다MATH
// 2개로 확장
"src/*.{ts,tsx}"

// 2 × 2 × 2 = 8개로 확장
"{a,b}/{c,d}/*.{ts,tsx}"

// 중괄호가 없으면 예산에 안 잡힌다
"src/**/*.ts"
규칙 하나의 paths 목록 전체가 확장 패턴 1,000개와 4 MiB라는 하나의 예산을 나눠 쓴다.
💣

초과하면 조용히 안 걸린다

예산을 넘길 패턴은 확장하지 않고 그대로 사용된다. 그러면 중괄호가 리터럴 문자가 되어 어떤 파일과도 매칭되지 않는다. 에러 없이 규칙만 조용히 죽는다.

📌

과거 버전에서는 더 나빴다

v2.1.217 이전에는 중괄호 그룹이 많은 paths 값이 시작 시점에 CLI를 멈추거나 크래시시켰다.

✅

실용적인 처방

중괄호는 확장자 묶음 한 곳에만 쓰고, 디렉터리 분기는 패턴을 여러 줄로 나열해 표현한다. 목록이 길어지는 편이 곱셈 폭발보다 안전하다.

확장 폭발은 에러 없이 규칙을 지운다

✓
무효한 패턴이 있어도 그 규칙의 다른 패턴은 정상 작동한다 — 하나가 전체를 망가뜨리진 않는다

4부 ① · 파일 읽기

지시만이 아니라 파일 읽기도 비용이다

.claude/settings.json — 읽기 자체를 막는다DENY
{
  "permissions": {
    "deny": [
      "Read(./**/dist/**)",
      "Read(./**/build/**)",
      "Read(./**/*.generated.*)",
      "Read(./vendor/**)"
    ]
  }
}
.gitignore에 있는 경로는 검색에서 이미 자동 제외된다. deny 규칙이 필요한 대상은 저장소에 체크인된 벤더 SDK와 생성 코드다.
🚧

deny가 미치는 범위

내장 파일 도구와 cat·head·grep·find 같은 인식된 Bash 명령의 인자를 막는다. 다만 재귀 검색 결과에서 걸러 주지는 않고, 스스로 파일을 여는 임의의 서브프로세스도 막지 못한다.

🧠

코드 인텔리전스로 탐색을 대체한다

심볼 정의와 호출부를 찾느라 파일을 훑는 대신 언어 서버에 물어본다.

/plugin install typescript-lsp@claude-plugins-official

TypeScript·Python·Go·Rust 등이 공식 마켓플레이스에 있다. 각 개발자 머신에 해당 언어 서버 바이너리가 필요하다.

제외 설정이 안 읽을 것을 정하고, 코드 인텔리전스가 남은 것을 뒤지지 않게 한다 — 둘은 짝으로 쓸 때 효과가 크다.
컨텍스트를 먹는 건 지시보다 파일이다

체크아웃도 필요한 폴더만

{
  "worktree": {

      ".claude",
      "packages/api",
      "packages/shared"

  }

루트 레벨 파일은 항상 체크아웃되지만 루트 레벨 디렉터리는 아니다 — .claude를 직접 적어야 워크트리 안에서 규칙과 스킬을 쓸 수 있다
✓
경로는 저장소 루트 기준이며 디렉터리만 나열한다. 세션의 모든 워크트리가 같은 목록을 공유하므로 서브에이전트가 쓸 경로도 함께 적는다
추가 방식CLAUDE.md·규칙스킬
additionalDirectories절대 안 됨안 됨
--add-dir · /add-dir환경변수 있을 때만로드됨
🔑

지시까지 가져오려면

CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1

이 변수를 켜야 --add-dir로 붙인 디렉터리의 CLAUDE.md·.claude/rules/가 로드된다. additionalDirectories 설정에는 이 변수가 아무 효과가 없다.

📂

파일 접근과 지시 로딩은 별개다

읽고 쓸 수 있다는 것과 그 폴더의 규약이 로드된다는 것은 다른 문제다. 형제 패키지를 고치는데 그쪽 규약이 안 들어오는 상황이 여기서 생긴다.

4부 ③ · 압축 이후

긴 세션에서 살아남는 것과 아닌 것

대상/compact 이후어떻게 돌아오나
프로젝트 루트 CLAUDE.md 살아남는다 디스크에서 다시 읽어 세션에 재주입된다
하위 폴더 CLAUDE.md 사라진다 그 디렉터리의 파일을 다시 읽을 때 재로드
paths: 규칙 사라진다 패턴에 맞는 파일을 다시 다룰 때 재로드
대화로만 준 지시 사라진다 돌아오지 않는다 — 파일에 적어야 지속된다
🧭

분산 설계의 유일한 대가

온디맨드 로딩은 컨텍스트를 아껴 주는 대신 압축을 견디지 못한다. 긴 세션에서 "아까는 지키더니 지금은 안 지킨다"의 정체가 대개 이것이다.

📄

패키지를 넘나드는 작업이라면

계획을 먼저 세우고 저장소 안 마크다운 파일로 저장한다. 긴 세션은 도중에 압축되지만 파일로 남긴 계획은 살아남는다. 공유 타입을 고치고 모든 호출부를 따라가는 작업은 한 세션에 통째로 넘기는 편이 결정의 일관성이 높다.

가벼움과 지속성은 맞바꾸는 것이다

전부 켜면 이렇게 동작한다

packages/api/에서 세션을 시작했을 때 실제로 벌어지는 일이다.

✓
루트 CLAUDE.md와 packages/api/CLAUDE.md가 로드되고, packages/web/의 지시는 들어오지 않는다
✓
packages/api/와 packages/shared/의 파일을 읽고 고칠 수 있다
✓
dist/·build/ 하위 파일 읽기는 차단된다
✓

✓
마이그레이션 파일을 건드리는 순간 migrations 규칙이 합류한다
✓

점검표 · ANTI-PATTERNS

지금 내 설정에서 여덟 줄만 확인하자

1
규칙 파일을 쪼개 놓고 paths:를 안 붙이지 않았나 — 폴더만 나눈 것은 조건부가 아니다
2
@import로 나눠 놓고 가벼워졌다고 믿지 않았나 — 토큰은 그대로다
3
한 파일이 200줄을 넘지 않았나 — 넘으면 준수율부터 떨어진다
4
코드베이스에서 유추 가능한 내용(디렉터리 구조·의존성 목록)을 적어 두지 않았나
5
반드시 막아야 할 것을 CLAUDE.md 문장으로만 적어 두지 않았나 — 훅이나 deny로 걸어야 한다
6
계층 간 모순된 지시를 방치하지 않았나 — Claude가 임의로 하나를 고른다
7
중괄호를 여러 겹 써서 확장 예산을 넘기지 않았나 — 에러 없이 규칙이 죽는다
8
매일 바꿀 범위를 claudeMdExcludes로 관리하지 않았나 — 시작 디렉터리를 바꾸는 게 맞다

잘 쪼갠 설정은 세션마다 가벼워진다
