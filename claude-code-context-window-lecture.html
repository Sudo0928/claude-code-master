03
개념 정의 · WHAT

기억이 아니라 매번 다시 읽는 작업대

컨텍스트 윈도우는 모델이 답을 만들 때 참조할 수 있는 모든 텍스트다. 학습한 지식과는 완전히 다른, 이번 세션만의 작업 기억이다.
1

Claude는 대화를 '기억'하지 않는다

턴마다 처음부터 전부 다시 읽는다. 어제 일을 기억하는 게 아니라, 매번 같은 서류 뭉치를 다시 펼치는 것에 가깝다.

2

내가 친 글자는 극히 일부다

시스템 프롬프트, CLAUDE.md, 스킬 목록, 파일 내용, 도구 출력이 대부분을 차지한다. 내 프롬프트는 소수점 단위다.

3

크기에는 한계가 있다

모델마다 정해진 상한이 있다. Claude Code는 한계에 다다르면 자동으로 요약(압축)해서 세션을 이어간다.

4

많이 넣는다고 좋아지지 않는다

토큰이 늘수록 정확도와 회상률이 떨어진다. 공간을 얼마나 가졌느냐보다 무엇을 담았느냐가 중요하다.

컨텍스트는 창고가 아니라 작업대다

●

화면에 그대로 보인다

○

아예 안 보인다

시스템 프롬프트, CLAUDE.md, 자동 메모리, 경로별 규칙, 훅이 돌려준 컨텍스트.

가장 흔한 오해

"별로 얘기한 것도 없는데 왜 벌써 차지?"

그래서 컨텍스트 관리는 "말을 줄이는 것"이 아니라 "읽히는 걸 줄이는 것"이다.

핵심 원리 · CONTEXT ROT

많이 넣을수록 흐려진다

Anthropic 공식 문서가 이름 붙인 현상이다 — 토큰이 늘수록 정확도와 회상률이 떨어진다. 창을 키우는 것으로는 해결되지 않는다는 뜻이다.
💰

비용이 는다

🎯

정확도가 떨어진다

가장 무서운 쪽. 창 안에 남아 있어도 찾아 쓰지 못한다. 신호 대비 잡음이 커지기 때문이다.

그래서 원칙은 하나다 — 공간이 얼마나 남았느냐보다, 지금 무엇이 들어 있느냐. 관리의 목표는 창을 다 쓰는 게 아니라 필요한 것만 남기는 것이다.

판단 기준 · COMPACT vs CLEAR

둘 중 어느 쪽을 눌러야 하나

🗜️

/compact — 이어서 할 때

대화를 구조화된 요약으로 대체한다

같은 작업을 계속할 때. 지금까지의 결정과 맥락은 지키면서 공간만 되찾는다.

  • 리팩터링을 계속 이어갈 때
  • 긴 디버깅 중간
  • 새 작업을 시작하기 직전
🧹

/clear — 넘어갈 때

대화를 비우고 0에서 시작한다

관련 없는 작업으로 넘어갈 때. 이전 맥락은 도움이 안 되면서 자리만 차지하고 답을 흐린다.

  • 버그 수정 → 새 기능 개발
  • 다른 저장소·다른 모듈
  • 이전 대화는 /resume으로 복귀 가능
초점을 준 압축이 훨씬 낫다 — /compact 인증 버그 수정 흐름 위주로 처럼 뒤에 지시를 붙이면, 자동 압축이 알아서 추측하는 대신 내가 고른 것을 남긴다. 한계에 닿으면 Claude Code가 자동으로 압축해 주지만, 내가 먼저 하는 편이 항상 낫다.
같은 일은 compact, 다른 일은 clear

본문은 실제로 쓸 때 로딩

  • 커밋·배포·발송처럼 내가 직접 부를 것

  • 도구 스키마는 필요할 때 검색해 불러온다

오해 정리 · MYTHS

"창을 키우면 되잖아?" — 아니다

📏

오해 ① 1M 창이면 관리는 필요 없다

일부 모델은 100만 토큰 창을 지원한다. 하지만 컨텍스트 로트는 창 크기와 무관하게 작동한다. 잘 관리된 20만이 방치된 100만보다 낫다. 큰 창은 한 번에 처리해야 할 거대한 입력을 위한 것이지, 관리를 대신해 주지 않는다.

💵

오해 ② 캐시되면 컨텍스트도 안 먹는다

프롬프트 캐시는 같은 앞부분을 다시 보낼 때 값을 깎아주는 장치다. 공식 문서 표현대로, 캐시된 부분도 컨텍스트 창은 그대로 차지한다. 캐시는 비용 문제를 줄여줄 뿐, 정확도 문제는 그대로다.

🤖

오해 ③ 자동 압축이 알아서 해준다

한계에 닿으면 자동으로 압축돼 세션은 안 끊긴다. 다만 무엇을 남길지 알아서 추측한다. 내가 /compact 무엇 위주로 라고 지정하면 훨씬 정확하다.

🧹

오해 ④ /clear 하면 다 날아간다

대화만 비워질 뿐 CLAUDE.md와 설정은 그대로다. 이전 대화도 디스크에 남아 /resume으로 돌아갈 수 있다. 아까워하지 말고 자주 쓰자.

큰 창은 관리의 대체재가 아니다
